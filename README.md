# VELLIUM

Тёмный лендинг и первая версия личного облачного дневника питания. Приложение рассчитано на русский интерфейс и мобильный экран.

## Запуск

```powershell
npm install --silent
Copy-Item .env.example .env.local
# Укажите URL и publishable key проекта Supabase VELLIUM
npm run dev --silent
```

Лендинг открывается на `/`, дневник — на `/app`.

## Что работает сейчас

- Личный профиль взрослого пользователя и ориентир энергии/БЖУ по формуле Миффлина — Сан Жеора с ручной настройкой калорий.
- Ручной ввод блюда с пересчётом пищевой ценности с 100 г на указанную порцию.
- Дневной баланс, история за последние семь дней, удаление записи.
- Идея следующего блюда из небольшого локального списка после первой записи. Подсказка ориентируется на остаток калорий и белка, не выдаётся за медицинский совет.
- Регистрация и вход через Supabase Auth; сохранение личного профиля и блюд в Supabase (Франкфурт).
- Экспорт профиля и записей в JSON, удаление профиля и записей из облака.

Профиль и записи хранятся в проекте Supabase VELLIUM во Франкфурте. В браузере библиотека Supabase сохраняет сессию входа. Семейные профили, распознавание фото и сканер пока не включены; на лендинге они обозначены как функции следующих этапов.

Отдельный проект Supabase VELLIUM (`jabznldqaeqtgtczulwa`, Франкфурт) содержит таблицы `nutrition_profiles` и `meal_entries`. Схема находится в [миграции](supabase/migrations/20261019000100_personal_nutrition_core.sql): обе таблицы защищены RLS, записи блюд дополнительно ограничены связным ключом на профиль того же владельца. Доступ двух синтетических пользователей проверен в откатываемой транзакции; после неё таблицы и тестовые аккаунты пусты. Перед запуском регистрации настройте Site URL и Redirect URLs в Supabase Auth для нужного домена, почтовую отправку и резервное копирование.

## Следующие этапы

1. Проверка полного цикла Auth/дневника на двух подтверждённых тестовых аккаунтах и настройка почтовой отправки.
2. Серверный FastAPI для распознавания фото, текста и аудио через Gemini с подтверждением результата перед записью.
3. Сканер штрихкодов/GS1 DataMatrix и каталог продуктов с проверяемым источником.
4. Семейные профили, история и аналитика, Excel, PWA и доступность на реальных устройствах.
5. Аудит VPS, резервная копия старого сайта и отдельный план размещения без вмешательства в действующие сервисы.

Публичный запуск в России требует отдельной юридической проверки трансграничной обработки и локализации персональных данных. Пользователь выбрал Франкфурт для хранения данных; это техническая настройка, а не заключение о соответствии 152‑ФЗ. До завершения проверки не размещайте приложение как публичный сервис для реальных пользователей.
